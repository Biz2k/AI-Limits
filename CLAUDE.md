# AI Limits — память проекта

Программа для Windows 11: лимиты **Claude Code** (подписка Pro) и **Google Antigravity**
(только модели Gemini) для нескольких Google-аккаунтов. Владелец — автор репозитория (Biz2k),
общение на русском. Только стандартная библиотека Python 3.13 (Python из Microsoft Store).

## Как работать с владельцем
- Проверки окна идут на русском языке (`"lang": "ru"` в подменённых настройках) плюс отдельный шаг на трёх языках.
- Общение на русском; правки интерфейса он присылает со снимками экрана и проверяет в собранном exe сам.
- После каждой правки кода: прогнать `python tests\run_tests.py` (и дополнить проверки под новую правку), пересобрать `..\AI Limits.exe`, перезапустить программу,
  если она была запущена, обновить `CLAUDE.md` (и `ROADMAP.md`/README, если затронуты), сделать локальный коммит.
- В отчёте прямо говорить, что проверено и чем, а что нет.
- Push и теги на GitHub — только после прямого «да»; спрашивать одним вопросом в конце.
- Новая сборка, которой он пользуется: поднять `version.py`, тег `vX.Y.Z`.

## Файлы
- **С версии 1.2.0 код разнесён по модулям** (ни один файл не длиннее ~500 строк). Логика:
  - `storage.py` — пути папки данных, DPAPI (`protect_*`/`unprotect_*`), журнал ошибок, `atomic_write_json`.
  - `winapi.py` — вызовы Windows через ctypes: процессы, командная строка, порты, окна, версия файла,
    диспетчер учётных данных (`_wincred_*`), `_run_hidden`.
  - `cloud.py` — OAuth-ключи, `accounts.json`, `http_json`, Claude (`claude_fetch`), облако Antigravity
    (`cc_post`, `ag_fetch`, `ag_login`), `protect_stored_secrets`.
  - `ide_local.py` — запущенная IDE: `IdeServer`, `find_ide_servers`, `local_ide_info`, `stop_ide`/`start_ide`,
    `ide_version`, журнал `_ide_log`.
  - `ide_switch.py` — смена аккаунта IDE: копии, запись токена, `ide_switch_account`, `ide_restore_backup`,
    `ide_login_browser`.
  - `history.py` — история лимитов: `record` (запись в `history.csv`), `load` (чтение раз за запуск и чистка
    старше 60 дней), `forecast`/`forecasts`, `series` для графика. Пишет только окно; консольная версия — нет.
  - `limits.py` — консольная версия (`python limits.py`, `add`, `accounts`, `remove`, `switch-ide <email>`,
    `switch-ide --browser`, `switch-ide <email> --test-rollback`, `restore-ide [--yes]`, `keys`, `-w`, `--json`),
    вывод, кэш лимитов. **Единая точка входа для окна**: `L.<имя>` для имени, которого нет в самом `limits`,
    ищется в модулях-частях (`__getattr__` модуля, значение всегда текущее).
  - Правило внутри логики: модули подключают друг друга целиком (`import cloud`) и обращаются как `cloud.http_json`,
    а не `from cloud import http_json` — иначе подмена в проверках и изменяемые значения (`G_CLIENT_ID`, пути)
    не будут видны из других модулей. Переменные с `global` живут в том модуле, где меняются.
- Окно:
  - `limits_gui.pyw` — настройки (`load_settings`/`save_settings`), класс `App(PopupsMixin, TrayMixin)`: создание
    окна, обновление данных (`refresh` → `_on_part` → `_all_done`), `render`, смена аккаунта; `main()`.
  - `ui_theme.py` — цвета, шрифты, `INTERVALS`, `Bar`, `FlatButton`, `Tooltip`, `color_for`, `short_reset`.
  - `ui_cards.py` — `CardView`, `RowView`, `_set`, `_vis` (обновление на месте).
  - `ui_popups.py` — `PopupsMixin`: меню ⚙, `confirm`, `keys_dialog`, предупреждение о пороге.
  - `ui_tray.py` — `TrayMixin`: иконка окна, уход в трей, меню иконки, мини-окно, подсказка.
  - `ui_history.py` — `HistoryMixin`: запись истории после обновления (`update_history`), прогнозы (`self.fc`,
    `fc_line`, `forecast_soon`, `forecast_alerts`), окно графика `show_history`.
  - `i18n.py` — языки интерфейса: `T("русская строка", имя=значение)`, `set_lang`, `lang`, `day`, таблица
    `TEXTS` (русский исходник → английский, украинский). См. «Язык интерфейса».
  - `autostart.py` — автозапуск (раздел реестра Run). В `autostart.py` и `ui_tray.py` путь к главному файлу окна —
    константа `GUI_SCRIPT` (не `__file__` модуля).
  - Примеси пользуются полями `App` через `self`; новые методы окна класть в подходящую примесь.
- `tests\` — проверки на вымышленных данных: `test_backend.py` (шифрование, ключи, заголовок версии IDE, вызовы
  Windows, копии, `restore-ide`, смена аккаунта с откатом, отсутствие токенов в выводе), `test_gui.py` (окно на
  подменённых данных: карточки, обновление на месте, меню, окно ключей, смена аккаунта, предупреждение, меню трея),
  `run_tests.py` — общий запуск. История в проверках пишется во временную папку (`storage.APPDIR`). В проверках подменять функцию **в модуле-владельце** (`cloud.http_json = …`),
  для окна — через `L.` (`L.ag_fetch = …`). Проверка окна идёт внутри `mainloop` (шаги — генератор, `drive`):
  фоновые потоки программы зовут `root.after`, а он работает только при запущенном цикле.
- `tray.py` — иконка в трее на чистом ctypes/Win32 (свой поток и скрытое окно класса `AILimitsTrayWnd`),
  одна копия программы (мьютекс `AILimits.SingleInstance`; второй запуск шлёт `WM_APP_SHOW`).
- OAuth-ключи Antigravity (с версии 1.1.0, `load_google_keys` в `limits.py`): переменные окружения
  `ANTIGRAVITY_OAUTH_CLIENT_ID/_SECRET` → `%APPDATA%\ai-limits\keys.dat` (DPAPI; пишет `set_google_keys` — команда
  `python limits.py keys`; окно ввода в меню ⚙ владелец убрал 12.11.2026 как лишнее) → `local_keys.py` (только при запуске
  из исходников; **не в git**, образец — `local_keys.example.py`). **В exe ключей нет**: `local_keys` подключается
  по имени строкой (`importlib`), чтобы PyInstaller его не вшил, из `build_exe.cmd` убран `--hidden-import local_keys`.
  Без ключей запросы Google дают «нет OAuth-ключей Antigravity — задайте их командой: python limits.py keys»
  (`_need_google_keys`). У владельца ключи перенесены в `keys.dat` 12.11.2026; `local_keys.py` из папки
  исходников удалён по его просьбе.
- `version.py` — `__version__` (единственное место версии); `python version.py <файл>` пишет описание версии для
  PyInstaller (`--version-file`, делает `build_exe.cmd`). Новая сборка для пользователя: поднять версию здесь,
  собрать, закоммитить, поставить тег `vX.Y.Z`.
- `ROADMAP.md` — план разработки по этапам; отмечать выполненное там.
- `.gitignore`, `.gitattributes` (`* -text`: файлы хранятся как есть — `build_exe.cmd` в CP866, остальные исходники

## Данные пользователя
- **Шифрование (версия 1.1.0):** DPAPI через ctypes (`_dpapi`, энтропия `ai-limits`, без окон). Строки в JSON —
  `dpapi:<base64>` (`protect_text`/`unprotect_text`), файлы целиком — метка `AILIMITS-DPAPI-1` + шифр
  (`protect_bytes`/`unprotect_bytes`; файл без метки читается как есть). Зашифрованы: `refresh_token` в
  `accounts.json` (`load_accounts` расшифровывает, `save_accounts` шифрует; не расшифровавшийся токен хранится
  как был, аккаунт показывает «токен не расшифрован… добавьте заново»), `keys.dat`, в `ide_backups\` — файлы
  `gemini_antigravity_*` и `app_storage_*` (`credential-user-scope*`, `user_scope_*`, `meta_*` — открытые, токенов
  в них нет). Данные прежних версий перешифровывает `protect_stored_secrets()` при запуске окна и консоли.
  Расшифровать может только та же учётная запись Windows на том же компьютере; программы под этой учётной
  записью — могут. Проверка: в папке данных не должно быть строк `1//`, `ya29.`, `GOCSPX`.
- `%APPDATA%\ai-limits\`: `accounts.json` (refresh-токены Google, зашифрованы), `keys.dat`, `cache.json`, `gui.json` (настройки окна),
  `history.csv` (история лимитов: время UTC, ключ `claude`/email, окно, %, время сброса; токенов нет),
  `ai_limits.ico` (для exe), `ide_switch.log` (журнал смены аккаунта IDE, токены скрыты), `ide_backups\` (копии
  учётных данных IDE перед сменой аккаунта), `app.log` (необработанные ошибки: `L.install_error_log()` ставит
  `sys.excepthook` и `threading.excepthook`, окно — `root.report_callback_exception`; запись — `L.log_exception`,
  с версией; больше 512 КБ → `app.log.1`; токены скрывает `_mask_secrets`). При разборе сбоя сначала смотреть его.
- Python из Store: **новые** файлы в `%APPDATA%\ai-limits` попадают в папку пакета (так 12.11.2026 туда лёг
  `keys.dat` — в настоящую папку скопирован вручную), существующие читаются и пишутся на месте. Поэтому данные

- Python из Store перенаправляет `%APPDATA%` в
  `%LOCALAPPDATA%\Packages\PythonSoftwareFoundation.Python.3.13_qbz5n2kfra8p0\LocalCache\Roaming\ai-limits`;

- Процесс pythonw из Store называется `pythonw3.13.exe`.

## Решения и предпочтения пользователя (интерфейс)
- Только модели Gemini в Antigravity; строки «Неделя» и «5 часов»; у Claude неделя сверху.
- Дата сброса недели — над полосой слева от отсчёта, по-русски (пн…вс); у 5-часовых — только время, мелко и бледно.
- Значок плана: «PRO»/«ULTRA». Метка «● IDE» у текущего аккаунта IDE, кнопка «→ в IDE» у остальных.
- Кнопки сверху справа: ⚙, «Обновить» (кнопку «В трей» пользователь убрал 12.11.2026). В трей окно уходит кнопкой
  «—» и/или крестиком — по настройкам в меню ⚙ (см. «Настройки в меню ⚙»). При наведении на иконку в трее —
  мини-окно с полосами над иконкой (`Shell_NotifyIconGetRect`, NOTIFYICON v4).
- Меню ⚙ — своё (Toplevel), не системное: «Добавить Google-аккаунт», «Убрать Google-аккаунт» (раскрывающийся список),
  переключатели — нарисованные чекбоксы (пустой квадрат виден и без отметки), автообновление и порог — ряды кнопок.
  Внизу меню — «Открыть папку данных» и бледная строка с версией (`AI Limits 1.0.0`).
  У порога есть «выкл» (`warn = 0`: без всплывающего предупреждения, цвета полос как при 80%). Правый край меню — по правому
  краю кнопки «Обновить», за окно не выходит.
- Предупреждение о пороге (`check_alerts` → `show_alert`): один раз при пересечении — всплывающее окно справа над
  часами (рабочая область экрана, `SPI_GETWORKAREA`): плавно проявляется (250 мс), висит 5 с, плавно гаснет (450 мс),
  ✕ закрывает сразу. Звука и мигания кнопки в панели задач нет (пользователь убрал). В самом окне — цвет полос
  (жёлтый с 70%, красный с 90%).
- История и прогноз (версия 1.3.0, расчёт и тексты изменены в 1.4.1 по замечаниям владельца от 13.11.2026):
  - **Недельный лимит:** всё набранное за последние сутки текущего периода считается расходом одного дня, даже
    если данных меньше суток (нужен отрезок не короче часа и рост не меньше 0,5 %). Владелец работает сессиями:
    растягивать темп сессии на круглые сутки нельзя — это было его главное замечание. **5 часов:** темп сессии
    за последние 90 минут (отрезок не короче 10 минут). После падения значения (сброс) счёт идёт заново.
  - Значения из кэша («≈») в историю не пишутся и прогноза не имеют.
  - Текст: «при таком темпе хватит на 2 дня 5 часов, до вс 18:03» (`i18n.duration` — склонения на трёх языках).
    Строка под полосой (жёлтая, мелкая) есть, **только если** лимит кончится раньше сброса.
  - Мини-окно трея: только недельные прогнозы, без слова «неделя» («Claude — хватит на …, до …»), до трёх строк.
  - Щелчок по строке лимита — окно графика (`show_history`, закрывается как `confirm`).
  - Всплывающее предупреждение по прогнозу **выключено по умолчанию** (владельцу оно мешало): галочка
    «Предупреждения по прогнозу» в меню ⚙ (`forecast_alerts` в `gui.json`). Включённое — только недельные лимиты,
    об одном лимите не чаще раза в час и только если расчётное время сдвинулось на полчаса и больше
    (`ALERT_GAP`, `ALERT_SHIFT`, состояние `fc_alert_state`); показывается в одном окне с пороговым.
  - У Claude окно недельного лимита называется «Неделя» (раньше «Неделя (все модели)»; старое название в
    `history.csv` читается как новое — `OLD_NAMES` в `history.py`).
- **Язык интерфейса (версия 1.4.0):** английский по умолчанию, русский, украинский; выбор — ряд кнопок «Язык» в
  меню ⚙, хранится в `gui.json` (`lang`), применяется сразу (`set_lang` в `ui_popups.py`: карточки и строка
  «Максимум» пересоздаются, прогнозы пересчитываются). В коде строки остаются **русскими** и оборачиваются в
  `T(...)`; подстановки только именованные (`T("Добавлен {email}", email=…)`), f-строки с кириллицей в окне не
  писать. Каждую новую строку добавлять в `TEXTS` в `i18n.py` — проверка `test_translations` падает, если у строки
  из `T("…")` нет английского и украинского варианта или не совпадают подстановки. Названия окон лимитов
  («Неделя», «5 часов», «Неделя (все модели)») и источников («облако», «данные IDE Antigravity») в данных, кэше и
  истории остаются русскими — это ключи; переводятся при показе (`T(name)`). Не переведены: консольная версия
  (`limits.main` ставит русский), журналы, сообщения исключений Windows.
- Внизу: серое «Максимум» (обычный шрифт 9), синий email, серая «→», зелёный % — по остатку **недельного** лимита.
- Окно показывается сразу; Claude, IDE (`local_ide_quota`) и каждый Google-аккаунт грузятся в своих потоках
  (`refresh` → `_on_part` → `redraw`), у ещё не загруженных карточек — «Загрузка…», при обновлении старые данные
  остаются без пометок. Данные IDE важнее облачных для того же аккаунта.
- Без мигания (12.11.2026): карточки **не пересоздаются**. `CardView`/`RowView` создаются один раз, `render` строит
  описание (`spec`) каждой карточки и вызывает `CardView.update` — меняются только изменившиеся значения (`_set`
  сравнивает с прошлым значением; `Bar.set`; показ/скрытие через `grid_remove`). Набор карточек меняется только при
  добавлении/удалении аккаунта (`self.card_order`). `redraw` пропускает вызов, если `repr(self.data)` не изменился.
  При обновлении уже показанных данных `render` вызывается один раз — в `_all_done` (по частям `_on_part` рисует,
  только пока есть карточки «Загрузка…»; иначе облачные данные на миг подменяли бы данные IDE).
  Кнопка «Обновить» при загрузке не меняет текст (иначе прыгает ⚙), только бледнеет.
- Подтверждения («→ в IDE», «Убрать Google-аккаунт») — своё тёмное окно `confirm()` (Toplevel без рамки, как меню ⚙),
  не системный messagebox: появляется под вызвавшей кнопкой, в пределах рабочей области её монитора; «Да»/Enter,
  «Нет»/Esc/щелчок мимо.
- Меню иконки в трее (правый щелчок) — тоже своё тёмное окно (`show_tray_menu`; `tray.py` отдаёт щелчок через
  `on_rclick` вместо системного `TrackPopupMenu`): «Открыть», «Обновить», «Выход»; появляется над курсором,
  закрывается выбором, Esc и щелчком мимо (`_tray_menu_watch` следит за кнопками мыши — окно без рамки может
  не получить фокус).
- Меню ⚙ закрывается при сворачивании окна, уходе в трей и закрытии (`<Unmap>` окна, `to_tray`, `on_close`).
- Строка статуса под заголовком: «Обновлено ЧЧ:ММ · авто N» — время последнего полного обновления (`_updated_at`).
  Зелёное «IDE теперь работает под …» держится 10 с и сменяется этой строкой; ошибки смены аккаунта — 20 с
  и до следующего обновления.
- При запуске (после первой полной загрузки) высота окна подгоняется по нижней строке. Надписи «% = израсходовано» быть не должно.
- Иконка в панели задач: AppUserModelID `AILimits.Monitor` + свойства окна (IPropertyStore), иначе Windows
  показывает иконку пакета Python.

## Смена аккаунта IDE (`ide_switch_account`)
- Прямая подстановка токена выбранного аккаунта из `accounts.json` без открытия окна браузера Google (клиент OAuth у AI Limits тот же, что и у входа IDE).
- Места хранения учётных данных IDE Antigravity:
  1. Windows Credential Manager: запись `gemini:antigravity` (пользователь `antigravity`, тип `CRED_TYPE_GENERIC`, сохраняемость `CRED_PERSIST_LOCAL_MACHINE`).
     В `CredentialBlob` лежит JSON с полями: `token` (`access_token`, `refresh_token`, `expiry`, `expires_in`, `token_type`), `auth_method: "consumer"`, `id_token_email`, `writer_id`.
  2. `%APPDATA%\Antigravity\app_storage.json`: ключ `agy.onboarding.lastLoginUsername` с email выбранного аккаунта.
  3. `%APPDATA%\Antigravity\credential-user-scope`: область пользователя (хэш для authstore плагинов). Удаляется или восстанавливается из per-user кэша, при старте `language_server` пересоздаёт её под текущий аккаунт.
- **Обязательный бэкап перед любым изменением**:
  В `%APPDATA%\ai-limits\ide_backups\` сохраняются `gemini_antigravity_<ts>.json`, `app_storage_<ts>.json`, `credential-user-scope_<ts>` и `meta_<ts>.json`.
  Хранятся только 5 последних копий (`_prune_ide_backups`); копии с токенами зашифрованы DPAPI (см. «Данные пользователя»).
  Файлы `user_scope_<email>` — кэш области по аккаунтам, не удаляются.
- Цикл переключения:
  1. Если IDE уже работает под нужным аккаунтом — ничего не делаем.
  2. Свежий access-токен Google: `http_json(G_TOKEN_URL, …)` с refresh-токеном аккаунта.
  3. `backup_ide_credentials()`: бэкап прежних учётных данных.
  4. `stop_ide()`: `taskkill /IM Antigravity.exe` **без `/F`**, ожидание до 10 с. После закрытия окна процессы
     `Antigravity.exe` **остаются висеть в фоне** (проверено 12.11.2026) — поэтому, как только окон нет
     (`_ide_window_count() == 0`), остатки завершаются `taskkill /F /T`. Пока окно открыто (вопрос о несохранённых
     файлах), принудительно не завершаем: через 10 с ошибка «Antigravity не закрылся за 10 с», учётные данные не тронуты.
     Оставшиеся `language_server` с `--override_ide_name antigravity` завершаются по PID.
  5. `_ide_write_account()`: токен в Credential Manager (`_wincred_write`), `lastLoginUsername` в `app_storage.json`,
     `credential-user-scope` — из кэша аккаунта либо удаляется.
  6. `start_ide()`: запуск `Antigravity.exe` (detached).
  7. Проверка: `find_ide_servers()` (`GetUserStatus` локального `language_server`) раз в секунду, до 90 с.
  8. Сбой на шагах 5–7 → **откат**: `stop_ide()` → `restore_ide_credentials(meta)` → запуск IDE, если она была запущена.
     Откат делается, только если IDE показала другой аккаунт или её сервер отвечает без входа. Если сервер за 90 с
     вообще не найден — `IdeSwitchUnverified` без отката (жёлтое «проверьте аккаунт в самой IDE»): 12.11.2026 в 09:15
     аккаунт на деле сменился, а сервер молчал 90 с, и откат вернул старый аккаунт зря. Причина молчания не выяснена.
     С версии 1.0.2 в `ide_switch.log` на каждом шаге ожидания пишется строка «Ожидание N с (опрос M с): …» —
     процессы `language_server`, их порты и ответ каждого порта (`find_ide_servers(diag)`), плюс запущен ли
     `Antigravity.exe`; при повторе молчания причину искать там.
  9. «IDE была открыта» (для запуска после отката и в `restore-ide`) — это окно Antigravity (`_ide_open`), а не
     процесс: после закрытия IDE остаётся фоновый `Antigravity.exe` без окна (sidecar).
- Проверка отката: `python limits.py switch-ide <email> --test-rollback` (`bad_token=True`) подставляет в IDE
  заведомо негодный токен; ожидается «IDE не вошла в аккаунт за 90 с» и возврат прежнего аккаунта.
  **Проверено вживую 12.11.2026 в 14:37** (запуск через Python из Store): сервер IDE со 2-й секунды отвечал
  «входа нет», через 90 с откат, IDE запущена и показала прежний аккаунт; всего 98 с. Заодно видно, что Python
  из Store пишет журнал и файлы `%APPDATA%\Antigravity` в настоящие папки (перенаправленной папки не появилось).
- Ручной возврат: `python limits.py restore-ide [--yes]` (`ide_restore_backup`, `latest_ide_backup`) — закрывает IDE,
  сохраняет нынешние учётные данные новой копией, возвращает последнюю копию, запускает IDE, если была открыта.
  Повтор команды отменяет возврат. Проверено на подменённом хранилище, вживую нет.
- После смены аккаунта окно (`_switch_ide_go` → `_ide_expect`) обновляется сразу и повторяет обновление каждые 3 с,
  до 10 раз, пока в данных IDE не появится новый аккаунт (`_all_done`).
- Проверено 09.11.2026 (версия Gemini, до доработок): 4 переключения подряд между тремя аккаунтами, по ~5 с,
  `GetUserStatus` показывал нужный email. 12.11.2026 пользователь переключал кнопкой «→ в IDE» из собранного exe
  (журнал 09:15–09:19: успех за 5–10 с). Отказ при незакрывшейся IDE сработал вживую (ещё с ожиданием 30 с);
  откат сработал один раз — тот самый лишний, см. п. 8.
  Не проверено, работает ли чат Gemini в IDE с нашим токеном (у него только `cloud-platform` и `userinfo.email`).
- Запасной способ через окно Google — `ide_login_browser()` (`python limits.py switch-ide --browser`): `AuthLogout` → `Login {}`
  (сам открывает «Вход – Google Аккаунты»; проверено 09.11.2026). `LoginWithBrowser` в IDE 2.29 отключён (HTTP 500 «deprecated»).
- Кнопки «→ в IDE» показываются для всех аккаунтов, кроме текущего вошедшего в IDE, если IDE запущена или
  `Antigravity.exe` найден (`L.ide_installed()` — без PowerShell: `render` идёт в потоке интерфейса).
- Удаление аккаунтов — только в меню ⚙ («Убрать Google-аккаунт»), на карточках ✕ нет.

## Настройки в меню ⚙ (добавлено 12.11.2026)
- «Сворачивать в трей» — `minimize_to_tray`: кнопка «—» прячет окно в трей (`<Unmap>` → `_on_unmap` → `to_tray`).
- «Сворачивать в трей при закрытии» — `close_to_tray` в `gui.json`; ✕ окна вызывает `on_close` → `to_tray`,
  настоящий выход — `quit_app` (пункт «Выход» в меню иконки трея). С этой галочкой иконка в трее есть **всегда**,
  в том числе при открытом окне (`tray_always`); без неё — только пока окно спрятано в трей.
- «Автозапуск после старта системы» — значение `AI Limits` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  (`set_autostart`/`autostart_enabled`; отметка читается из реестра). Команда — путь к текущему exe с ключом
  `--autostart` (старый `--tray` — то же самое): если включено «Сворачивать в трей при закрытии», программа стартует
  сразу в трее, иначе — обычным окном. Если exe перенесли — выключить и включить отметку заново.

## Ограничения / что не удалось
- Автоклассификатор Claude Code раньше запрещал подмену User-Agent под IDE (12.11.2026 запрос по прямой просьбе
  владельца прошёл) и чтение самим Claude файлов учётных данных IDE
  (`%APPDATA%\Antigravity\…`). Чтение/запись учётных данных IDE самой программой — осознанное решение владельца
  (реализация от Gemini, принята в основную версию 12.11.2026); Claude содержимое этих записей и бэкапов не читает,
  а Credential Manager проверяет на своей тестовой записи (`ai-limits:selftest`).
- Почему облако не отдаёт Gemini аккаунтам вне IDE (проверено 12.11.2026): программа шлёт `User-Agent: antigravity`,
  и `daily-cloudcode-pa` на `retrieveUserQuotaSummary` возвращает всем трём аккаунтам (план Google AI Pro, проект
  `aicode-consumers`) только группу «Claude and GPT models» (weekly + 5h). По сообщениям сторонних проектов
  (t3code #21115, sub2api #8578, октябрь–ноябрь 2026) группа «Gemini Models» (`gemini-5h`, `gemini-weekly`) отдаётся
  только клиенту, назвавшемуся свежей версией IDE; старым версиям — нет, части строк — 403.
  **Проверено 12.11.2026 по просьбе владельца на одном аккаунте:** тот же токен и тело `{"project":"aicode-consumers"}`,
  `User-Agent: antigravity/hub/2.24.0` (хватает и без скобок с `aidev_client`) → приходят обе группы: «Gemini Models»
  (weekly + 5h с остатком и временем сброса) и «Claude and GPT models».
  **Внесено в версии 1.0.1 по решению владельца**, в 1.0.2 версия берётся сама: `cc_user_agents()` в `limits.py` даёт
  порядок заголовков — `antigravity/hub/<версия установленного Antigravity.exe>` (из свойств файла, `ide_version()`;
  только если она новее `CC_IDE_VERSION_MIN = 2.24.0`), затем `antigravity/hub/2.24.0`, затем безымянный `antigravity`.
  Переменная окружения `ANTIGRAVITY_USER_AGENT` заменяет первые два. `cc_post` переходит к следующему только на
  HTTP 403 и запоминает принятый. Проверено 12.11.2026 на трёх аккаунтах: с `antigravity/hub/2.31.2` приходят неделя
  и 5 часов. Если у аккаунтов вне IDE снова пропала строка «5 часов» или источник стал «облако · действующий
  лимит» — Google перестал принимать эти версии (обновить IDE или поднять `CC_IDE_VERSION_MIN`). `fetchAvailableModels` и `retrieveUserQuota`
  дают один лимит на модель.
- При запуске через Python из Store запись в `%APPDATA%\Antigravity` может уйти в перенаправленную папку пакета —
  не проверялось; переключение проверено только из exe.
